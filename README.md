# Drop

Grab-style ride-hailing portfolio app by **Bell**. Phase 3: **live tracking polish + driver full-screen nav + in-trip chat + auto-translate**.

Free tiers only (Expo **dev build** — not Expo Go, Render free web service, Vercel hobby, Supabase free, Stripe test mode later). Map tiles, geocoding, and routing use free OSM-compatible services with **no paid keys**.

## Monorepo

npm workspaces (`apps/*`, `packages/*`). Node **22+** (see `.nvmrc`). Install once from the repo root:

```bash
npm install
```

## Auth

Unauthenticated mobile users see the auth stack (M02 login, M03 sign up, forgot password, optional phone OTP). A signed-in user with `profiles.role` null sees M04 role select (writes `rider` or `driver` only). Then the app routes to rider or driver mode.

Admin (`apps/admin`): A01-style login. Next.js 16 `proxy.ts` refreshes the Supabase session; the dashboard server-checks `role === admin`. Everyone else sees `/not-authorized`.

Express verifies the Supabase JWT (JWKS at `SUPABASE_URL/auth/v1/.well-known/jwks.json` via `jose`, HS256 fallback if `SUPABASE_JWT_SECRET` is set) and serves `GET /me` `{ id, role, trip_pin_enabled }` by reading `profiles` with the **user JWT + anon key** (no service role required). Both paths require issuer `${SUPABASE_URL}/auth/v1` (trailing slash stripped) and audience `authenticated`. JWKS allows `ES256`/`RS256`; the secret path is `HS256` only.

Admin stays gated when Supabase env vars are missing (redirect to `/login`); it never fail-opens the dashboard.

`profiles.trip_pin_enabled` is `false` by default. Users can read their own value; only `role = admin` may change it (trigger + `private.is_admin()`).

### Supabase dashboard (Bell)

1. Create a free project. Copy the project URL and **anon** key into the env files below. Do not commit real values.
2. Run the SQL files in `supabase/migrations/` in order (or `supabase db push`). Do **not** apply them from CI.
   - `20261110120000_profiles.sql` — profiles + admin guard (already applied live).
   - `20261110180000_rides.sql` — `ride_status` / `vehicle_type` enums, `rides`, `ride_pins`, `driver_locations`, RLS, `accept_ride`, `nearby_requested_rides`, `verify_trip_pin`, Realtime publication (`rides` + `driver_locations` only). **Already applied live — do not edit this file.**
   - `20261110200000_nearby_rides_hardening.sql` — `create or replace` on `nearby_requested_rides` only: clamp `radius_m` to **10 km**, compute `distance_m` from **rounded** pickup coords, ceil that distance to **250 m**. Same function signature / `NearbyRide` shape. **Already applied live — do not edit this file.**
   - `20261111090000_trip_chat.sql` — `profiles.preferred_language`, `messages` (+ RLS, `messages_guard`, `ride_peer`), Realtime publication for **messages only** (`ride_pins` stays unpublished). **Apply in the SQL editor. Do not apply from this repo’s CI, and do not apply anything to a live DB from an agent.**
   - `20261118100000_carpool.sql` — **new file only** (do not edit earlier migrations). `carpool_*` tables in `public` on the same `drop` project, shared `auth.users` / `public.profiles`. RLS, `carpool_book_seat` (atomic, error `ที่นั่งนี้เพิ่งถูกจอง`), discovery RPCs without exact coords or rider ids. Realtime: **`carpool_seats` + `carpool_messages` only** (never `ride_pins`). **Apply in the SQL editor. Do not apply from CI.**
3. **Authentication → Providers → Email**: enable email + password. Decide **Confirm email** (if on, sign-up returns no session until the user clicks the mail).
4. **Authentication → URL configuration**:
   - Site URL: admin origin (local `http://localhost:3000`, then the Vercel URL).
   - Redirect URLs: `http://localhost:3000/**`, `https://<admin-domain>/**`, `drop://auth/callback`.
5. **Phone OTP** (optional): add an SMS provider under Auth providers. Then set `EXPO_PUBLIC_ENABLE_PHONE_OTP=true` in `apps/mobile/.env`. Default is **false** because SMS is not free-tier by default.
6. **Realtime**: the rides migration adds **only** `rides` and `driver_locations` to `supabase_realtime`. The trip-chat migration adds **`messages`**. **`ride_pins` must not be published** (PIN values would leak). Confirm Database → Publications → `supabase_realtime`. The rider subscribes to their own ride row (finding → assigned) and to the assigned driver’s `driver_locations` (interpolated marker + throttled OSRM refresh). Chat is delivered over Realtime on `messages`. PIN is fetched via `GET /rides/:id`, not Realtime (the rider **and admin** see `trip_pin`; the driver never does). Drivers **cannot** `SELECT` requested rows (RLS), so they will not receive those Realtime events either. The driver app polls `GET /rides/nearby` (`nearby_requested_rides`: rounded pickup, no `rider_id`, no dropoff, radius clamped to `NEARBY_RIDES_MAX_RADIUS_M` = 10 km, `distance_m` from the rounded pickup then ceiled to 250 m) about every 3s while online. Chat channels reconnect with exponential backoff on `CHANNEL_ERROR` / `TIMED_OUT` / `CLOSED`, AppState foreground, and NetInfo.
7. Promote a staff user to admin in SQL (users cannot self-assign admin):

```sql
update public.profiles set role = 'admin' where id = '<auth user uuid>';
```

   Admins can enable trip PIN for a rider with `update public.profiles set trip_pin_enabled = true where id = '<rider uuid>';` (non-admins cannot).

`SUPABASE_SERVICE_ROLE_KEY` is optional for `/me` and Trip PIN (`verify_trip_pin` is a security-definer RPC the assigned driver calls with their user JWT). Set it on Render so the chat endpoint can persist `translated_text` / `source_lang` / `target_lang` (those columns are not granted to `authenticated`). Without it, messages still deliver with `translated_text` null.

## Map, search, fare, rides

The map uses **MapLibre Native** (`@maplibre/maplibre-react-native` + its Expo config plugin). That is **not** in Expo Go — use a [development build](https://docs.expo.dev/develop/development-builds/introduction/).

Tiles: configurable `EXPO_PUBLIC_MAP_STYLE_URL`. Default [OpenFreeMap](https://openfreemap.org) liberty (dark boards use OpenFreeMap dark when the env is unset). Alternative: `https://demotiles.maplibre.org/style.json`. **Attribution:** © OpenStreetMap contributors · OpenFreeMap.

Geocoding: Photon (`https://photon.komoot.io/api`) or Nominatim via `EXPO_PUBLIC_GEOCODER_URL`. Requests send a Drop `User-Agent` / `Referer`, debounce **500ms+**, require **3+** characters, and abort in-flight searches (no autocomplete hammering). Long-press / drag a pin and reverse-geocode.

Routing: OSRM via `EXPO_PUBLIC_OSRM_URL` (default `https://router.project-osrm.org` demo). The map draws the polyline and shows distance / duration.

**Fare: no formula.** `estimateFare(distanceM, durationS, vehicleType)` in `packages/types` always returns `null` (`TODO(fare-formula)`). The UI shows **ราคาประมาณ —**. `fare_estimate` is stored as `null`.

Ride API (JWT middleware, same as `/me`):

| Method | Path | Who |
|--------|------|-----|
| `POST` | `/rides` | rider creates pickup/dropoff + `vehicle_type` `car`\|`bike` |
| `GET` | `/rides`, `/rides/:id` | rider own; assigned driver; admin all. Drivers do **not** see requested rows. |
| `GET` | `/rides/nearby?lat=&lng=&radius_m=` | driver matching queue (`nearby_requested_rides`). `radius_m` clamped to 10 km in Express **and** SQL (`NEARBY_RIDES_MAX_RADIUS_M`). `distance_m` is from the rounded pickup, then ceiled to 250 m. |
| `POST` | `/rides/:id/accept` | `accept_ride` RPC: first-accept-wins, caller `role=driver` and `<> rider_id` |
| `POST` | `/rides/:id/decline` | driver dismisses a still-requested ride |
| `POST` | `/rides/:id/arrive` | assigned driver |
| `POST` | `/rides/:id/start` | PIN via `verify_trip_pin` when required, else confirm |
| `POST` | `/rides/:id/cancel` | rider or assigned driver |
| `PUT` | `/driver-location` | driver upserts their `driver_locations` row |
| `GET`/`POST` | `/rides/:id/messages` | in-trip chat. POST translates on the server (never blocks on provider failure) |

Trip PIN lives in **`ride_pins`**, not on `rides`, and **not** in Realtime. The rider (and admin) can `SELECT` it; the driver cannot. Accept is **only** `accept_ride()` (security definer, atomic `status=requested` and `driver_id is null`). Riders may cancel or edit non-status/non-driver fields; the guard trigger rejects rider writes to `driver_id` or to any status except `cancelled`. `verify_trip_pin` / start require `auth.uid() = driver_id`, `role=driver`, and `driver_id <> rider_id`. On accept, if `profiles.trip_pin_enabled` is true, a crypto-random 4-digit PIN is generated in `rides_guard` and shown only on the rider’s R05 card. The driver enters it (DN03); the server compares through HMAC (attempt limit 5). Otherwise the driver confirms (DN03b).

SQL attack-path assertions: `supabase/tests/rides_security.sql` (throwaway DB; apply profiles + rides + hardening first) and `supabase/tests/chat_rls.sql` (after trip_chat). Server Jest mirrors the same rules, including the 10 km radius clamp, 250 m distance buckets, distance-from-rounded-pickup, admin `GET /rides/:id` returning `trip_pin` while a driver never does, chat participant/impersonation/read-only-after-complete, and translation fallback.

Live tracking: the rider map interpolates the driver marker (position + heading) between Realtime location updates, refreshes the OSRM route/ETA at most once every ~15 s and only after ~40 m of movement, and tears down every Realtime channel on unmount / ride-status change.

Driver full-screen nav: a **⤢ Full screen** pill on D02/D03/D04 (and L-D02–L-D04), not D01. One mounted `MapView` + `fullscreen` state. Hidden bottom sheet + `StatusBar`, turn banner, Recenter, mini sheet (name + ETA, Call, Chat, ✕ Exit), SOS on the in-trip boards. Android `BackHandler` exits. `expo-keep-awake` while navigating.

In-trip chat: `messages` RLS (rider, assigned driver, admin SELECT; rider/assigned driver INSERT as themselves while accepted/arrived/in_progress). Translated columns cannot be forged by clients. UI: R06 / DN12 / L-Chat overlay, `ChatBubble`, driver quick-replies. Auto-translate is documented in [`docs/translation.md`](docs/translation.md).


```bash
cp apps/server/.env.example apps/server/.env
npm run dev -w @drop/server
# http://localhost:3001/health → {"status":"ok"}

```


## เพื่อนร่วมทาง carpool-core Phase C1

Pure TypeScript in `packages/carpool-core`. **Not wired into Drop mobile/admin.** Drop’s `estimateFare` stub is unchanged. `apps/carpool-web` (Phase C2) imports this package for fare / drop-off / trunk math — do not duplicate it. Run `npm test -w @drop/carpool-core` (picked up by root `npm test` / CI `lint-typecheck-test`).

### Fare / ค่าโดยสาร

`RATE_THB_PER_KM = 7` (overridable). **EN:** `mainFare = mainRouteKm × rate`, split equally among seats that are **open AND booked** (closed/unbooked pay 0). Taxi and private car use the same math; on a private car the **owner-driver is one payer** (cost-sharing, **no wage**). A passenger-requested off-route stop adds `detourKm × 2 × rate` **to that passenger only**. Detour km are not part of `mainRouteKm`. Luggage does not affect fare. Amounts are 2-decimal THB via integer satang; leftover satang go to payers in ascending id order so the sum matches the total.

**TH:** ค่าหลัก = กม. หลัก × อัตรา หารเท่ากันเฉพาะที่นั่งเปิดและจองแล้ว (ปิด/ยังไม่จองจ่าย 0). แท็กซี่กับรถส่วนตัวใช้สูตรเดียวกัน รถส่วนตัวเจ้าของรถที่ขับนับเป็นผู้จ่าย (แชร์ค่าใช้จ่าย ไม่มีค่าจ้าง). จุดแวะนอกเส้นทาง: `กม.อ้อม × 2 × อัตรา` เฉพาะคนนั้น. สัมภาระไม่กระทบค่าโดยสาร. คิดเป็นสตางค์จำนวนเต็ม.

Worked examples (`rate = 7`):

- **Taxi** A/B/C, 12 km, B detour 1.5 km: main `84` ÷ 3 = 28; B +`21` → **A 28, B 49, C 28** (total **105**).
- **Private car + driver**, same trip: main `84` ÷ 4 = 21; B +`21` → **A 21, B 42, C 21, driver 21** (total **105**).
- **Rounding:** 10 km / 3 payers = 70 THB = 7000 satang → **23.34 + 23.33 + 23.33**.

### Drop-off order / ลำดับลงรถ

Shortest `pickup → d1 → d2 → …`. Brute-force all permutations for **n ≤ 4** (24). **n > 4 throws** (`TOO_MANY_RIDERS`; OSRM later — no silent fallback). Pluggable async distance; default haversine (meters). Tie-break: lexicographically smaller id sequence.

ลองทุก permutation เมื่อไม่เกิน 4 คน; เกิน 4 โยน error. ฟังก์ชันระยะทางเปลี่ยนได้ ค่าเริ่มต้น haversine.

### Trunk / ท้ายรถ

Uniform `s = min(frameW/W, frameH/H)`, rect centered in the frame. Short side is at least **40%** of the matching frame side (scale is raised if needed; the long side may overflow). Corner radius **8%** of the rect’s shorter side. Luggage `H×W×D` cm: `usedVol = Σ`, `fillHeight = H·s·usedVol/(W·H·L)` capped at rect height, `overflow = usedVol > W·H·L`, plus `fillRatio`.

สเกลเท่ากัน จัดกลางเฟรม ด้านสั้นอย่างน้อย 40% ของด้านเฟรมที่คู่กัน มุมโค้ง 8% ของด้านที่สั้นกว่า.

Full formulas and tests: [`packages/carpool-core/README.md`](packages/carpool-core/README.md).
